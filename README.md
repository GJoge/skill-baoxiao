## 🎯 工作原理

本工具采用**三阶段执行模型**，确保数据在写入前经过用户确认：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  阶段1:提取  │ → │  阶段2:写入  │ → │  阶段3:合并  │
└─────────────┘    └─────────────┘    └─────────────┘
  发票识别            填写表格           PDF合并
  数据提取            Word文档           最终输出
  生成报告
```

**设计原因**：Python 非交互式执行无法暂停等待用户输入。三阶段设计允许用户在阶段1和阶段2之间复核并修改 `data_report.json` 文件。

## ✨ 功能特性

### 1. 📄 发票类型自动识别与归类

自动识别发票内容（非文件名），按类型重命名并归类：

| 类型 | 识别关键字 | 输出文件名 | 说明 |
|------|-----------|-----------|------|
| **机票** | 航空、航班、承运人、民航、座位等级、登机 | `jipiao1.pdf`, `jipiao2.pdf`... | 航空运输电子客票行程单 |
| **火车票** | 铁路、车次、二等座、高铁、动车、12306 | `huoche1.pdf`, `huoche2.pdf`... | 铁路电子客票 |
| **住宿** | 住宿、酒店、宾馆、住宿费、房费、客房 | `zhusu1.pdf`, `zhusu2.pdf`... | 酒店/宾馆住宿费发票 |
| **滴滴电子发票** | 滴滴、发票号码、价税合计 | `滴滴电子发票A.pdf`... | 滴滴出行增值税电子普通发票（金额计入统计） |
| **滴滴行程单** | 滴滴、行程单、行程记录 | `滴滴出行行程报销单A.pdf`... | 滴滴出行行程报销单（仅归档，金额不计入） |
| **其他交通** | 地铁、公交、出租车、一卡通、乘车码 | `交通费发票A.pdf`... | 地铁、公交、出租车等交通费用 |
| **退改签** | 退票、改签、变更 | `退改签1.pdf`... | 机票/火车票退改签费用 |

### 2. 💰 智能数据提取

从发票中提取关键信息：

- **金额提取**：识别"价税合计"小写金额，自动区分各类费用
- **日期提取**：使用 OCR + pdfplumber 双重校验提取航班/车次日期
  - 自动排除"填开日期"，只保留实际出行日期
  - 处理 OCR 常见错误（如 "11月" 误识为 "1月"）
- **城市提取**：提取出发和到达城市名称（自动排除北京作为中转站）
  - 机票：从 "出发城市/到达城市" 字段提取
  - 火车票：从 "出发站/到达站" 提取，去除 "南站/北站" 等后缀

### 3. ✅ 数据合理性校验

自动检查提取的数据是否合理：

| 校验项 | 规则 | 警告提示 |
|--------|------|---------|
| **金额范围** | 机票 ¥300-8000，火车 ¥20-3000，住宿 ¥100-3000，滴滴 ¥2-800 | 金额超出范围时警告 |
| **冬季日期** | 检测 1月/2月 日期（可能是 11月/12月 OCR 错误） | 提示可能是 1月→11月 误识别 |
| **日期跨度** | 多张机票日期跨度不超过 1 年 | 跨度异常时警告 |
| **未来日期** | 日期不超过当前时间 +1 年 | 发现未来日期时警告 |
| **历史日期** | 日期不早于当前时间 -2 年 | 发现过期日期时警告 |

### 4. 📝 Excel 报销表自动填写

自动填写 Excel 报销表格，支持以下单元格：

| 项目 | 数量单元格 | 金额单元格 | 日期单元格 | 说明 |
|------|-----------|-----------|-----------|------|
| **城市** | E4 | - | - | 多个城市用顿号分隔，如"成都、绵阳" |
| **火车** | E6 | F6 | - | 火车票数量和金额 |
| **机票** | E7 | F7 | J4(最早), M4(最晚) | 机票数量和金额，日期范围写入 J4/M4 |
| **退改** | E8 | F8 | - | 退改签费用 |
| **滴滴** | E10 | F10 | - | 仅统计**滴滴电子发票**金额，行程单不计入 |
| **住宿** | - | O9 | - | 住宿费用总额 |

**自动跨 Sheet 复制**：将 Sheet1 的日期自动复制到 Sheet2
- Sheet1.J4 → Sheet2.D3 (最早日期)
- Sheet1.M4 → Sheet2.F3 (最晚日期)

### 5. 📄 Word 审批文档自动填写

自动查找工作目录中的 `.docx` 文件并填写：

| 填写内容 | 说明 |
|---------|------|
| **地点** | 填写所有城市名称，如"地点：成都、绵阳" |
| **到达单位** | 根据城市自动匹配对应单位 |
| **起止时间** | 填写最早日期至最晚日期 |

**城市到单位的映射规则**（可通过配置文件或 `--city-units` 参数自定义）：

工具支持两种配置方式（优先级从高到低）：

1. **命令行参数**: `--city-units "北京:总部,上海:分公司"`
2. **配置文件**: 创建 `config.yaml` 文件，参考 `config.example.yaml`

| 配置方式 | 示例 |
|---------|------|
| 命令行参数 | `--city-units "北京:总部,上海:分公司,广州:办事处"` |
| 配置文件 | `city_units:\n  北京: 总部\n  上海: 分公司` |

### 6. 💳 微信支付账单匹配（新增功能）

**用户需要提供**：微信支付账单导出文件（Excel 格式）

**功能说明**：
1. 在发票文件夹中自动查找包含 "微信支付账单" 的 `.xlsx` 文件
2. 读取账单中的**金额**、**交易单号**、**交易对方**信息
3. 将发票金额与账单金额进行匹配（精确匹配允许 <0.01 元误差，滴滴行程单支持 0.01~10 元差额匹配）
4. 将匹配到的**交易单号**自动添加到对应发票 PDF 的底部居中位置

**匹配逻辑**：
- **精确匹配**：发票金额与账单金额相差 `< 0.01` 元（即分位相同）
- **模糊匹配**（仅适用于滴滴行程单）：账单金额比发票金额多 `0.01 ~ 10` 元
  - 原因：滴滴行程单通常不包含高速路桥费，而微信账单可能包含
  - 示例：行程单金额 ¥45.00，账单金额 ¥48.50（含高速费 ¥3.50）
- **排除项**：自动排除 "扫二维码付款"、"微信红包" 等非发票交易

**输出效果**：
在每张匹配成功的发票 PDF 底部添加红色文字：
```
交易单号: 420000XXXXXXXXXXXXXXXXXXX
```

### 7. 📑 OFD 转 PDF

自动将电子发票的 OFD 格式转换为 PDF：
- 扫描发票文件夹中的所有 `.ofd` 文件
- 使用 `ofd2pdf` 工具批量转换
- 跳过已存在的同名 PDF（避免重复转换）

### 8. 📎 PDF 合并

按固定顺序将所有 PDF 合并为 `汇总打印.pdf`：

1. `biaoge.pdf`（报销表格）
2. `shenpi.pdf`（审批文件，如果存在）
3. `jipiao*.pdf`（机票发票，按编号排序）
4. `huoche*.pdf`（火车票，按编号排序）
5. `zhusu*.pdf`（住宿发票，按编号排序）
6. `滴滴*.pdf`（滴滴电子发票和行程单）
7. `交通费*.pdf`（其他交通费发票）
8. `退改签*.pdf`（退改签费用发票）

## 🚀 安装

### 环境检查缓存机制

为避免重复检查环境，工具使用缓存机制：

- 首次运行时检查依赖并写入标记文件 `~/.cache/baoxiao/.env_checked`
- 后续运行若标记存在，**直接跳过环境检查，立即执行脚本**
- 如需重新验证（如更新依赖后），手动删除标记：`rm ~/.cache/baoxiao/.env_checked`

```python
# 缓存检查逻辑
if os.path.exists(os.path.expanduser("~/.cache/baoxiao/.env_checked")):
    print("环境已验证，跳过检查，直接执行脚本")
else:
    # 执行环境检查和安装
    # 通过后写入标记
```

## ⚙️ 配置

### 配置文件方式（推荐）

工具支持通过 `config.yaml` 文件配置城市到单位的映射，避免每次都在命令行输入。

**步骤：**

1. **复制模板文件**

2. **编辑 config.yaml**
   ```yaml
   # 城市到单位的映射
   city_units:
     北京: 总部
     上海: 分公司
     广州: 办事处
     深圳: 研发中心
     # 添加更多...
   ```

3. **放置位置**（按优先级查找）
   - 当前工作目录 `./config.yaml`
   - 脚本所在目录 `scripts/config.yaml`
   - 用户配置目录 `~/.config/baoxiao/config.yaml`

### 命令行参数方式

如果不想使用配置文件，可以直接在命令行指定：

```bash
--city-units "北京:总部,上海:分公司,广州:办事处"
```

**优先级说明：** 命令行参数 > 配置文件 > 空配置

## 📖 使用方法

### 三阶段处理流程

本工具采用**三阶段执行模型**，确保数据准确性和可控性：

```
阶段1: 数据提取 → 阶段2: 数据写入 → 阶段3: PDF合并
```

---

### 阶段 1：数据提取（`--extract-only`）

从发票文件中提取所有关键数据，生成数据报告供复核。

**执行命令：**
```bash
python3 scripts/invoice_processor.py \
    --input-dir 发票 \
    --extract-only
```

**阶段 1 会自动完成：**

1. **OFD 文件转换**（如果存在）
   - 扫描发票文件夹中的 `*.ofd` 文件
   - 使用 `ofd2pdf` 工具自动转换为 PDF 格式
   - **转换失败处理**：若任何文件转换失败，立即停止执行，报告失败的文件名、原因和建议解决方法
   - 跳过已存在的同名 PDF

2. **微信支付账单处理**（如果存在）
   - 查找 "微信支付账单" `.xlsx` 文件
   - 提取金额、交易单号、交易对方信息
   - 与发票金额匹配
   - 将交易单号添加到对应发票 PDF 底部

3. **发票类型识别与重命名**
   - 使用 OCR 读取发票内容
   - 根据关键字识别发票类型
   - 按类型重命名文件（如 `jipiao1.pdf`、`huoche1.pdf`）

4. **数据提取**
   - 金额：提取"价税合计"小写金额
   - 日期：提取航班/车次日期（OCR + pdfplumber 双重校验）
   - 城市：提取出发和到达城市（自动排除北京）

5. **数据合理性校验**
   - 金额范围检查
   - 日期合理性检查
   - 日期交叉验证

**输出文件：**
- `data_report.json` - 数据报告，包含提取的城市、日期、金额、警告信息等

**data_report.json 示例：**
```json
{
  "cities": ["成都", "绵阳"],
  "cities_str": "成都、绵阳",
  "dates": {
    "earliest": "2025-11-26",
    "latest": "2025-11-28"
  },
  "amounts": {
    "jipiao": 1250.00,
    "huoche": 450.00,
    "didi": 120.50,
    "zhusu": 800.00,
    "tuigai": 0.00
  },
  "counts": {
    "jipiao": 2,
    "huoche": 1,
    "didi": 5,
    "zhusu": 2
  },
  "warnings": [],
  "needs_review": false
}
```

---

### 阶段 2：数据写入（`--write-data`）

根据确认的数据报告，写入 Excel 报销表和 Word 审批文档。

#### 未知城市处理流程

如果 `data_report.json` 中的 `unknown_cities` 字段不为空，**必须先处理未知城市**才能继续。工具会暂停并询问用户：

```
⚠️ 发现以下未知城市需要处理:
  - 纺阳

已识别到的所有城市（共3个）：
  - 北京 ✓ 已配置
  - 沈阳 ✓ 已配置
  - 纺阳 ⚠️ 未知

请选择处理方式：
1. 新增城市映射 - 将"纺阳"添加到config.yaml配置文件
2. 修正城市名称 - 修改data_report.json（如"纺阳"→"沈阳"）
3. 删除该城市 - 从data_report.json中移除"纺阳"

请回复选项编号（1/2/3）...
```

| 选项 | 处理方式 | 适用场景 | 后续操作 |
|------|---------|---------|---------|
| **1. 新增** | 添加到 `config.yaml` | 新城市，需要长期使用 | 询问单位名称 → 写入配置 → 重新执行阶段2 |
| **2. 修正** | 修改 `data_report.json` | OCR识别错误 | 询问正确城市名 → 修改报告 → 重新执行阶段2 |
| **3. 删除** | 从报告中移除 | 发票识别错误或不是差旅目的地 | 确认删除 → 移除城市 → 重新执行阶段2 |

> **提示**：显示所有已识别城市是为了帮助用户确认。例如"纺阳 ⚠️ 未知"而"沈阳 ✓ 已配置"，可判断"纺阳"是OCR错误，应选**选项2**修正为"沈阳"。

**执行命令：**
```bash
python3 scripts/invoice_processor.py \
    --output-excel biaoge.xlsx \
    --work-dir . \
    --write-data \
    --city-units "北京:总部,上海:分公司,广州:办事处"
```

**阶段 2 会自动完成：**

1. **读取数据报告**
   - 从 `data_report.json` 读取确认的数据

2. **填写 Excel 报销表**
   - 填写各类费用金额、数量
   - 填写城市名称到 E4 单元格
   - 填写日期范围到 J4/M4 单元格（中文格式）
   - 自动复制日期到 Sheet2

3. **填写 Word 审批文档**
   - 查找工作目录中的 `.docx` 文件
   - 填写地点、到达单位、起止时间
   - 根据城市映射自动匹配单位

---

### 阶段 3：PDF 转换和合并（`--merge-pdfs`）

将文档转换为 PDF 并合并为最终文件。

**执行命令：**
```bash

    --input-dir 发票 \
    --work-dir . \
    --merge-pdfs
```

**阶段 3 会自动完成：**

1. **Excel 转 PDF**
   - 将 `biaoge.xlsx` 转换为 `biaoge.pdf`

2. **Word 转 PDF**
   - 将 `shenpi.docx` 转换为 `shenpi.pdf`

3. **收集发票 PDF**
   - 按固定顺序收集重命名后的发票 PDF

4. **合并 PDF**
   - 按顺序合并所有 PDF
   - 输出 `汇总打印.pdf`

## 🔧 详细功能说明

### OFD 文件处理

如果发票文件夹中包含 OFD 格式的电子发票，工具会自动：

1. 检测所有 `.ofd` 文件
2. 调用 `ofd2pdf` 工具进行转换
3. 在同一目录生成同名的 `.pdf` 文件
4. 跳过已存在的 PDF（避免重复转换）

### 微信支付账单匹配详细流程

**用户操作：**
1. 从微信导出账单：我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单
2. 将下载的 Excel 文件放入"发票"文件夹
3. 文件名需包含"微信支付账单"（如：`微信支付账单_202501.xlsx`）

**自动处理流程：**
1. 读取账单的 F 列（金额）、I 列（交易单号）、C 列（交易对方）
2. 排除 "扫二维码付款"、"微信红包" 等非发票交易
3. 遍历所有发票 PDF，提取金额
4. 匹配发票金额与账单金额（精确匹配允许 <0.01 元误差，滴滴行程单支持 0.01~10 元差额匹配）
5. 在匹配成功的 PDF 底部居中添加红色交易单号

**注意事项：**
- 如果一张发票对应多笔微信交易，会添加所有匹配的交易单号
- 交易单号以红色字体显示在 PDF 底部
- 未匹配的发票会输出提示，可手动核对

### 日期提取的校验逻辑

工具使用多重校验确保日期准确性：

1. **OCR 识别**：高 DPI (400+) 识别发票图像中的日期
2. **pdfplumber 复核**：从 PDF 文本层提取日期进行交叉验证
3. **填开日期排除**：自动识别并排除"填开日期"，只保留实际出行日期
4. **冬季日期检查**：检测 1月/2月 日期，提示可能是 11月/12月 OCR 错误
5. **多日期排序**：多张机票按日期排序，检查跨度是否合理

### 城市提取规则

- **机票**：从"出发城市"、"到达城市"字段提取
- **火车票**：从"出发站"、"到达站"提取，自动去除"南站"、"北站"等后缀
- **北京排除**：北京作为中转站会被自动排除
- **重复去重**：同一城市多次出现只保留一次

## ⚠️ 注意事项

### data_report.json 字段说明

阶段1生成的数据报告包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `cities` | array | 提取的城市列表（可修改） |
| `cities_str` | string | 城市字符串，顿号分隔（可修改） |
| `unknown_cities` | array | 未知城市列表（未在config.yaml配置） |
| `dates` | object | `earliest`最早日期, `latest`最晚日期 |
| `amounts` | object | 各类发票金额：`jipiao`, `huoche`, `didi`, `zhusu`, `tuigai` |
| `counts` | object | 各类发票数量 |
| `warnings` | array | 数据校验警告信息 |
| `needs_review` | boolean | 是否需要复核（有警告或未知城市时为true） |

### 微信支付账单

1. **导出方式**：必须从微信官方渠道导出，确保包含交易单号列
2. **文件位置**：必须放在 `--input-dir` 指定的发票文件夹中
3. **文件名**：文件名需包含"微信支付账单"才能被识别
4. **匹配精度**：
   - 精确匹配：允许 <0.01 元误差（分位相同）
   - 滴滴行程单模糊匹配：允许账单金额比发票金额多 0.01~10 元（可能含高速路桥费）

### OCR 识别质量

1. **机票 PDF**：通常是扫描件，需要使用高 DPI (400+) 识别
2. **打印质量**：模糊、倾斜、低分辨率的 PDF 可能导致识别失败
3. **手工核对**：以下情况建议手工核对：
   - 金额接近范围边界
   - 1月/2月 日期（可能是 11月/12月 误识别）
   - 日期跨度超过 1 年

### 常见 OCR 错误

| 错误类型 | 示例 | 处理方式 |
|---------|------|---------|
| 月份误识 | "11月" → "1月" | 自动检测并警告，建议 pdfplumber 复核 |
| 日期误识 | "29日" → "9昌" | OCR 后处理自动修正 |
| 金额误识 | "¥1,250" → "¥1250" | 统一格式后处理 |

### 滴滴发票处理规则

- **电子发票**：统计金额，计入滴滴费用总额
- **行程单**：仅归档，金额**不计入**（避免与电子发票重复）
- **匹配逻辑**：行程单金额与电子发票金额可能一致，但只有电子发票计入总额

### 文件备份

- 重命名前自动创建备份到 `/tmp/invoice_backup/`
- 备份保留原始文件名，可随时恢复

### Excel 模板要求

- 必须包含 `sheet1` 工作表
- 如果有 `sheet2`，会自动复制日期过去
- 单元格格式会被保留（如日期显示格式）

### Word 文档要求

- 文档中需包含"地点"、"到达单位"、"起止时间"等关键词
- 工具会在表格中查找这些关键词并填写对应内容
- 未识别的城市会输出警告，需要手动填写
